# 工单状态流转规则

文档编号：KB-STATUS-001
适用场景：查询或变更工单状态、判断状态变更建议是否可执行
关键词：工单、状态、流转、待处理、处理中、已完成、已取消、建议、审批
相关文档：KB-LOGIN-001（无法登录处理规范）、KB-PAYMENT-001（支付成功但订单未更新）

## 状态定义

| 状态 | 含义 | 是否终态 |
|---|---|---|
| 待处理 | 新建工单的初始状态，还没有人接手 | 否 |
| 处理中 | 已被负责人接单，正在处理 | 否 |
| 已完成 | 问题解决并结单 | 是 |
| 已取消 | 用户撤回、重复工单或无需处理 | 是 |

## 允许的流转

| 当前状态 | 可以流转到 | 不可以流转到 |
|---|---|---|
| 待处理 | 处理中 | 已完成、已取消 |
| 处理中 | 已完成、已取消 | 待处理 |
| 已完成 | — | 任何状态 |
| 已取消 | — | 任何状态 |

- 待处理不能直接跳到已完成：必须先进入处理中，避免出现没人处理过就结单的工单。
- 已完成、已取消是终态，不能回退。需要继续跟进时新建工单，并在摘要中注明原工单编号。
- 除四种状态之外的值都视为非法，返回 `INVALID_ARGUMENT`。

## 变更工单的两种方式

1. **直接更新**：`PATCH /tickets/{ticket_id}/status`，适用于人工在后台改状态。
   新旧状态相同时直接返回当前工单，属于幂等操作，不算错误。
2. **建议 + 确认**：先 `POST /sessions/{session_id}/actions` 生成一条状态变更建议，再由人工 confirm、reject 或走审批接口确认。
   助手只能发起建议，不能直接改单；建议在确认之前不会影响工单。
   新旧状态相同时不生成建议，返回 `NO_STATUS_CHANGE`。

## 建议（action）的状态

| 状态 | 含义 |
|---|---|
| pending | 已生成，等待人工确认 |
| executed | 已确认并成功改单 |
| rejected | 人工拒绝 |
| stale | 生成建议之后工单已被别处改过，建议失效 |

- stale 的建议不能再执行，需要按工单当前状态重新发起建议。
- 拒绝只把 pending 改成 rejected，不校验工单当前状态；
  所以工单被别处改过之后，这条 pending 建议仍然可以拒绝。
- 已经是 stale 的建议再拒绝会返回 `ACTION_STALE`。

## 错误码对照

| 错误码 | HTTP | 含义与处理 |
|---|---|---|
| INVALID_ARGUMENT | 400 | 工单编号或状态为空，或状态名不在四种状态内 |
| TICKET_NOT_FOUND | 404 | 工单不存在，先核对编号 |
| INVALID_STATUS_TRANSITION | 409 | 流转不被允许，对照上面的流转表 |
| TICKET_CONFLICT | 409 | 并发更新失败，工单刚被别处改过，重新查询后再操作 |
| NO_STATUS_CHANGE | 409 | 新旧状态相同，不生成建议 |
| ACTION_NOT_FOUND | 404 | 建议不存在，或不属于该会话 |
| ACTION_STALE | 409 | 建议已失效，重新查询工单后重新发起 |
| ACTION_REJECTED | 409 | 建议已被拒绝 |
| ACTION_ALREADY_EXECUTED | 409 | 建议已经执行过，不能再拒绝 |
| APPROVAL_ALREADY_STARTED | 409 | 该建议已经发起过审批 |
| APPROVAL_NOT_WAITING | 409 | 审批不在等待状态，可能尚未发起或已经处理完 |

## 转交人工的条件

- 需要把已完成或已取消的工单恢复：终态不可回退，由人工判断是否新建工单。
- 建议反复变为 stale：说明有人在同时操作同一工单，需要人工协调。
- 工单编号存在但内容与用户描述明显不符：可能建错单，需要人工核对。
