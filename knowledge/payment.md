# 支付成功但订单未更新处理规范

文档编号：KB-PAYMENT-001
适用场景：用户反馈支付成功但订单未更新，以及由此引出的重复扣款、退款未到账问题
关键词：支付、扣款、订单、退款、对账、流水号、发票
相关文档：KB-STATUS-001（工单状态流转规则）、KB-LOGIN-001（无法登录处理规范）

## 需要收集的信息

| 信息 | 说明 |
|---|---|
| 订单号 | 平台订单号，不是支付渠道的流水号 |
| 支付渠道 | 微信、支付宝、银行卡、余额 |
| 金额与时间 | 实际扣款金额、扣款时间，精确到分钟 |
| 渠道流水号 | 支付渠道账单里的交易号，核对和退款都必须用到 |
| 凭证 | 扣款短信、账单截图、支付失败页面截图 |
| 账号 | 下单账号，用于确认订单归属 |

## 排查步骤

1. **先分清订单状态和支付状态**
   - 订单已关闭但用户已被扣款：支付成功、下单超时，属于待退款。
   - 订单显示未支付但渠道显示已扣款：等待渠道回调，或走人工对账。
   - 两边都显示成功：订单更新延迟，刷新或等待后重新查询。
2. **确认回调是否到达**
   - 渠道回调延迟通常几分钟内完成，超过 30 分钟未更新按异常处理。
   - 用户重复下单或重复点击支付时，重点检查是否产生了多笔流水。
3. **重复扣款**
   - 同一订单出现两笔成功流水：保留一笔，另一笔原路退回。
   - 不同订单各扣一笔：属于重复下单，按用户意愿退其中一笔。
4. **退款进度**
   - 先确认退款单是否已发起、渠道是否已受理。
   - 到账时效以渠道为准：余额类通常实时，银行卡一般 1~3 个工作日，个别银行可达 7 个工作日。
   - 未超过时效的，告知用户等待并提供退款单号；超过时效再转人工核查。

## 权限边界

- 助手只能查询订单与支付状态、整理信息、发起工单。
- 退款、冲红、修改金额必须由人工在后台操作，并且需要二次确认。
- 不能向用户承诺具体到账时间点，只能给出渠道的时效范围。
- 不能引导用户重新支付来“冲掉”上一笔，必须先确认上一笔的实际状态。

## 转交人工的条件

- 需要发起退款、冲红或调整金额。
- 渠道对账不平：流水号查不到、金额与订单不一致。
- 同一用户短时间内多笔支付失败，或存在盗刷、欺诈迹象（立即冻结并升级处理）。
- 退款超过渠道时效仍未到账。
- 涉及企业客户、大额订单或需要财务确认的场景。
